# Security policy

## Supported scope

Security fixes target the default branch and the currently deployed GitHub Pages
release. Dormant migration and local-only infrastructure is reviewed for repository
safety but is not a supported production service. Public generated state, release
integrity, source-access controls, privacy boundaries, workflow permissions, and
secret handling are in scope.

## Private reporting

Use **GitHub private vulnerability reporting** for `reklis/scotus-briefs`:
open the repository's **Security** tab, choose **Report a vulnerability**, and submit
the private advisory. If that option is unavailable, do not disclose sensitive
details publicly; ask the repository owner through a non-sensitive GitHub issue to
enable or provide a private reporting route.

Do not put vulnerabilities, credentials, source or extracted text, private evidence,
model payloads, exploit details, or personal data in a public issue or pull request.
Do not test against the Court website, GitHub Pages, or third-party services in a way
that disrupts service or exceeds documented access limits.

## Response expectations

A maintainer should acknowledge a private report within 7 days, provide an initial
assessment within 14 days, and coordinate remediation and disclosure through the
private advisory. These are targets, not a bounty or service-level agreement. We will
preserve reporter credit when requested and explain any material delay.
